## Additional blocking failure modes

- Webhook claim is not completion: failed or abandoned processing must be retryable. Use bounded processing leases and durable completion, with idempotent downstream side effects. Do not acknowledge an unfinished concurrent attempt as completed unless recovery is guaranteed.
- Stripe `checkout.session.completed` is not necessarily paid. Validate authoritative payment status and delayed-payment events, hold/payment/session binding, expected amount/currency/mode and account/test mode before fulfillment.
- Guest-supplied email is not proof of account ownership. Existing-account custom-token issuance is prohibited without independent authentication. Recovery must not create account takeover.
- External calls cannot be rolled back with a Firestore transaction: ensure crashes between provider creation and local persistence do not duplicate subscriptions, codes or mail.
- Cancellation/reschedule while credential programming and stale Seam events must not reactivate revoked access. Preserve desk-change occupancy and time-bound access semantics.
- Annual billing must use actual subscription paid-through dates, not a fixed 35-day expiry. Renewal events need authoritative subscription-owner mapping and current-state reconciliation.

## Test-quality rules

1. Import/invoke production functions or compiled deployed handlers; do not reimplement their logic inside tests.
2. Mock external boundaries, not the business logic being asserted. Include realistic Stripe payload shape for the configured API version and raw-body signature checks.
3. Exercise Firestore transactions and failure/retry boundaries in emulators, not only source-text regex assertions.
4. Record skipped cases and environmental failures explicitly; neither is a pass. Keep code, emulator, controlled-provider and production observations distinct.
5. Build both split booking bundles and the main functions bundle. Verify CI includes newly added tests and deployment filters cover changed source.
