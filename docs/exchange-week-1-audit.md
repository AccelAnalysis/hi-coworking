# Exchange Week 1 audit

Status reflects the repository at the start of this run plus corrective work completed here.

| Area | Prior status and relevant implementation | Launch issue / security concern | Week 1 action | Deferred |
|---|---|---|---|---|
| Authentication / registration | Working Firebase email/password pages at `/register` and `/login`; `authBeforeCreate` creates `users/{uid}` and role claims. | Both routes sent users to the general dashboard without organization onboarding. | Redirected successful registration/sign-in to `/exchange/onboarding`; preserved password reset and existing auth. | Email verification and social sign-in. |
| User profiles | Partially working `/profile`, `profiles`, verification and enrichment callables. | User-centric business profile is disconnected from organization ownership. | Organization onboarding no longer treats the user profile as payment authority. | Migrate suitable profile fields to organization profiles. |
| Organizations | Partially working `orgs`, `orgMembers`, `/org/dashboard`, `/org/settings`, and legacy `org_create`. | No search/claim path; client write helpers conflicted with server-only rules; duplicate control was slug-only. | Added normalized multi-source search, duplicate warnings, claim requests, atomic admin approval/rejection, competing-claim handling, claimant status, server creation, Free membership, and owner role. | Member invitation redesign. |
| Organization authorization | Partial owner/admin roles. | Existing Stripe checkout was user-level; browser selected tier and return URLs. | New checkout revalidates owner/admin or platform admin on the server. Firestore denies client mutation of membership, founder, and credit data. | Fine-grained organization permissions beyond three launch roles. |
| Exchange map | Prototype/partial. Homepage map renders the physical coworking location; RFx has `MarketplaceMap`. | No organization map backed by seeded organizations; home-address exposure risk. | Prepared safe coordinates only for non-home seed records; campaign reuses the existing preview without claiming a finished organization map. | Organization-marker map, clustering, and geocoding review. |
| Business directory | Partially working `/directory`; published user profiles, not organization records. | Seeded organizations were not searchable or visibly unclaimed. | New onboarding search reads seeded `orgs`, labels claim state, and minimizes displayed fields. | Convert directory cards and filters to organization-centric data. |
| RFx / opportunities | Substantial partial implementation at `/rfx`, `/rfx/new`, `/rfx/detail`, callable publish, suggestions, and map. | Monetization and credits are user-level; team documents explicitly incomplete. | Preserved working routes and documented truthful staged state. Central Exchange capability keys now exist. | Enforce organization entitlements on all RFx mutations; team document workspace. |
| Referrals | Partially working `/referrals` and server callables. | Directly mutates user credit balance and uses a separate ledger. | Preserved to avoid breaking working behavior; did not present those credits as Founding credits. | Move referral limits/spend to organization credit lots and capabilities. |
| Teaming | Partially working inside RFx; team creation/invites/roles exist. | Not a standalone organization entitlement flow; document area is a placeholder. | Preserved backend and safe limited messaging. | Organization-scoped teaming and shared documents. |
| Resources | Working/partial public spaces, events, bookstore, and authenticated library; advanced resource programs are not unified. | No central Exchange entitlement use. | Added `exchange.resources.browse` capability without overstating feature readiness. | Resource-program catalog and organization targeting. |
| Membership / billing | Existing user-level coworking plans and Stripe Checkout/webhooks were present. | Hard-coded price IDs; membership activation attached to users; success redirects could be confused with activation. | Added separate organization membership records, parameterized Founding price, fixed server URLs, signed-webhook synchronization, and return-state pages. | Billing portal and live mode. |
| Founder cap | Missing. | No authoritative limit or race-safe numbering. | Added 30-minute reservations and transactional active/reserved counts plus sequential 1–250 assignment. | Operational dashboard for reservations and continuity exceptions. |
| Credits | Existing mutable `users.credits` plus user transactions. | Not organization-level, no expiring lots, and renewal scheduler was not invoice-authoritative. | Added organization credit lots and immutable ledger; `invoice.paid` grants 25 once by invoice ID; 12-month expiration. | FIFO spend API and migration of existing user-credit actions. |
| Admin | Broad admin routes for members, orgs, verification, billing, events, territories, and analytics. | Direct org editing did not cover claim approval or founder operations. | Added `/admin/exchange-claims`, admin-only list/read/approve/reject callables, idempotent audit records, and server-only state. | Founder reconciliation and credit adjustment UI. |
| Notifications | Present and used by multiple modules. | No claim/membership notifications. | No launch-critical mutation. | Add claim decisions, invoice failures, and activation notifications. |
| Database / migrations | Firestore rules, no relational migrations. | New lifecycle records and indexes were missing. | Added additive collection model, composite indexes, server-only rules, deterministic seed verification, and idempotent import. | Historical backfill after staging dataset import. |
| API / functions | Many callables and one Stripe webhook. Existing USAspending implementation used an unsuitable recipient endpoint shape. | Organization matching source was disconnected and external calls needed to stay server-side. | Added server-only USAspending recipient autocomplete, local-source matching, dedupe, rate limiting, and sanitized results. | Award-history enrichment and monitoring/circuit breakers. |
| Environment | Stripe secrets existed; multiple hard-coded price IDs remain for legacy coworking plans. | No strict Founding price/product/mode validation or canonical return URL parameter. | Added `.env.example`, price/product/mode parameters, catalog validation before reservation, and a demo-project-only injected Stripe mock. | Rotate legacy coworking IDs into environment configuration. |
| Tests | Secure-foundation emulator coverage existed on current main. | PR #4 added only pure model tests. | Added 13 unit/import tests, seven emulator acceptance scenarios, server-only rule denial, two Playwright journeys, deterministic attached-source regeneration, and CI. | Real Stripe test-mode and staging smoke tests require external configuration. |
| Mobile / accessibility | AppShell and most forms are responsive; labels exist across auth. | New onboarding needed usable mobile actions and visible states. | Added stacked mobile layouts, labels, focus rings, loading, empty, pending, and errors. | Full keyboard/screen-reader audit of legacy modules. |
| Duplicate interfaces | General coworking pricing and user dashboard coexist with organization dashboard. | `$49` Virtual Member could be mistaken for Exchange Founding Membership. | Created a clearly separate `/exchange/founding` campaign and organization membership page; preserved space pricing. | Product-level information architecture consolidation. |

## Known launch dependencies

- Deploy Firestore rules and Cloud Functions.
- Import prepared seed data with authenticated Firebase Admin credentials.
- Create the Stripe test product/price, set required parameters/secrets, and configure the signed webhook.
- Run emulator/browser E2E with a test user. Local code cannot prove external Stripe or deployed Firebase behavior without those credentials.

## Week 2 priorities

Organization-centric directory/map; billing portal; founder operational reconciliation; notification hooks; and migration of RFx/referral/team actions from user-level monetization to Exchange entitlements.
